# Set up HouseCraft

1. Detect Git, Node.js, npm, a WebGL browser, an existing viewer checkout and its dependencies, Blender, and connected AgentCAD tools or other local CAD integrations. Show what is available and what is missing. Recommend the default viewer for validation and preview; it requires Node.js 22 or later and npm. Offer Blender or AgentCAD as optional authoring tools when relevant. Check what the connected AgentCAD tools already support before considering installation or configuration. Confirm the exact distribution and documented capabilities of any requested CAD or MCP tool before proposing it.
2. If the chosen tools require agent settings, use the current agent's documented configuration mechanism and prefer project scope. Get explicit approval before changing user-wide settings. Read existing settings, preserve unrelated entries, and show the exact proposed diff and any install commands before applying them. Install or enable only approved tools from their official sources. The default CLI needs no agent configuration or MCP server. Prefer local AgentCAD operations; use cloud processing or uploads only if the user explicitly requests them.
3. Use the official [HouseCraft Viewer](https://github.com/pankajvaghela/housecraft-viewer) release `v0.1.0` at commit `95ad9f7b45024184ad36d56c138cc5b6d2afcffd`. Reuse a trusted, clean checkout at that revision or clone the release to a tools directory outside the home project. Preserve any existing checkout and its changes. Before installing dependencies, verify the checkout with `git rev-parse HEAD` and require the exact commit above. If the release cannot be fetched or verified, report the issue instead of falling back to the default branch. If the user explicitly selects a local development checkout, record its commit and any uncommitted changes and identify it as a development checkout. Run `npm ci` from the viewer checkout, then `node bin/housecraft.mjs validate examples/two-room` and `node bin/housecraft.mjs preview examples/two-room --port 0`. Check the printed localhost URL and stop the temporary setup preview when finished.
4. Save the chosen capabilities, tool paths and versions, viewer checkout and ref, and readiness results in a local setup record outside the source repositories and portable house JSON. Use the host's local state directory for HouseCraft, keyed by project, and keep credentials out. Refresh the record on rerun. Report its path, what changed, and viewing readiness separately from optional authoring readiness. Authoring tools do not expand the viewer's supported project format. Hand off to [create-house](../create-house/SKILL.md) when the user wants to build a project.
